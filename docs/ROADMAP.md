# Дорожная карта: волны issues

Работа нарезана на волны. Волна закрывается целиком, прежде чем начинается
следующая: каждая следующая опирается на готовое и протестированное
предыдущее. Внутри волны задачи можно брать в любом порядке, если явно
не указана зависимость.

Условие завершения проекта из дизайн-документа: **полный функционал при
полном покрытии тестами физического ядра и игровой логики.** Поэтому в
каждой задаче критерии приёмки формулируются как проверяемые утверждения,
а не как «сделать красиво».

## Правила приёмки

1. **Физика и логика — только через тесты.** Любая задача из волн 1–5 и 9–10
   считается закрытой, когда пороги покрытия (90% строк, 85% ветвей по
   `packages/core` и `packages/game`) держатся, а новые сценарии описаны
   отдельными тестами.
2. **Рендер — через сравнение состояний.** Юнит-тестами не проверяется;
   приёмка требует видео состояний, ручной проверки в игровом масштабе при
   массовых разрушениях и регрессии производительности.
3. **Детерминизм.** Любая случайность идёт через сид. Два прогона с одним
   сидом дают идентичное состояние мира — на это есть тесты, и они не
   должны мигать.
4. **Спорные решения.** Критерий один: делает ли это планирование и
   разрушение веселее. Если задача усложняет, но не делает — она не берётся.

## Заливка issues в GitHub

```bash
# посмотреть план, ничего не создавая
npm run issues:plan

# создать метки, вехи и issues (нужен gh или GH_TOKEN)
GH_TOKEN=<token> node tools/issues/sync-issues.mjs --repo <owner>/<name>

# дополнительно закрыть задачи, помеченные в waves.yaml как done
GH_TOKEN=<token> node tools/issues/sync-issues.mjs --repo <owner>/<name> --close-done
```

Скрипт идемпотентен: повторный запуск не плодит дубликаты, а обновляет
тело и метки существующих issues, сопоставляя их по заголовку.
