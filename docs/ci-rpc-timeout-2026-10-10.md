# Исправление CI после расширения карты

База: `7e63e088d62be4e3eaec21ed51fc58cb5f43fcc3`.
Проблемный [прогон GitHub Actions](https://github.com/nsn99/teardown-vox/actions/runs/38045593760)
остановился на `test:cov`: 862 теста прошли, а два необработанных исключения
`[vitest-worker]: Timeout calling "onTaskUpdate"` прервали передачу результатов.
Тесты производительности, сборка и браузерная проверка после этого не запускались.

В Vitest 2.1.9 внутренний RPC имеет срок 60 секунд. Долгие синхронные
операции под покрытием могут задерживать подтверждение отчёта. Этот случай
исправлен разработчиками Vitest в [PR #8297](https://github.com/vitest-dev/vitest/pull/8297).
Такой же сбой уже записан в [отчёте патча от 8 октября](garage-hands-crane-2026-10-08.md).
Зафиксированы совместимые версии `vitest` и `@vitest/coverage-v8` — `4.0.18`.
Они поддерживают Node 20 и Node 22; игровой Vite остаётся на прежней версии.

Vitest 4 также проверяет фактическое время синхронных тестов. Построение,
разрушение и загрузка полной карты под покрытием уже занимали десятки секунд
в прежнем CI. Срок теста и общего хука установлен в 120 секунд, короткие
явные сроки интеграционных сценариев полной карты приведены к нему. Два
длинных прохода маршрутов имеют срок 600 секунд: один из них в исходном
журнале занимал более 300 секунд. Бюджеты игровых операций в `perf.test.ts`
и пороги покрытия 90/90/90/85 процентов сохраняются.

CI сохраняет вывод покрытия в `shots/test-coverage.log`, включает ошибки
в сводку и сохраняет исходный код завершения через `pipefail`. Весь job
ограничен 45 минутами, включая последующую проверку в браузере.

Проверка канала отчётов использует настоящие RPC обеих версий и задерживает
подтверждение `onTaskUpdate` на 65 секунд: версия 2.1.9 выдаёт исходную ошибку
через 60,05 секунды; версия 4.0.18 успешно завершает вызов через 65,01 секунды.

В следующем шаге обнаружился ложный провал проверки дыма. Реальная дальность
видимости уменьшалась с 300 до 14 метров, но разница средних яркостей всего
кадра составляла только 0,0063: осветление и затемнение разных частей сцены
компенсировались. Разница соответствующих пикселей области сцены составляла
0,1132. Прогон теперь измеряет среднюю абсолютную разницу яркости пикселей
без HUD, сохраняя порог 0,01. Источник дыма работает до получения снимка,
чистая область очищается от прежних эффектов, игрок стоит на земле.
Дополнительно проверяется уменьшение дальности тумана и её восстановление,
исчезновение ячеек после 60 расчётных секунд поля дыма и восстановление
изображения. Для сравнения PNG требуется установленный `canvas`.

## Выполненные проверки

Среда: Node.js 22.23.3, Vitest 4.0.18. Полный прогон покрытия с тремя
работниками завершился за 901 секунду: **868/868 тестов, 82/82 файла**,
без необработанных ошибок. Новый алгоритм V8-покрытия Vitest измерил:

| Показатель | Результат | Требование |
| --- | ---: | ---: |
| Строки | 98,92% | 90% |
| Операторы | 96,34% | 90% |
| Функции | 98,23% | 90% |
| Ветви | 90,74% | 85% |

Перф-регрессия: **10/10**, с прежними бюджетами. Проверка типов, ESLint,
валидация плана issues и production-сборка прошли. `npm ci --dry-run`
подтвердил согласованность манифестов и lock-файла. Все 49 файлов готовой
игры, включая JavaScript, CSS, HTML и ресурсы, совпадают с исходной сборкой;
служебный `tsconfig.tsbuildinfo` исключён из этого сравнения.

Полный браузерный прогон прошёл в Chromium 143 с программным SwiftShader,
без ошибок страницы и консоли. Проверены загрузка расширенной карты,
геометрия, разрушение, ремеш, освещение склада, дым и кадр симуляции.
В проверке дыма дальность уменьшилась с 300 до 7 метров, изменение изображения
составило 0,1257; после рассеивания осталось 0 ячеек, разница с чистым кадром —
0,0000. Медиана затрат главного потока на сцену при обрушении — 0,30 мс;
медиана шага симуляции при разрушении — 3,00 мс, среднее — 5,03 мс.

Команды проверки:

```bash
npm ci
npm run typecheck
npm run lint
npm run issues:plan
npm run test:cov -- --maxWorkers=3
npm run test:perf -- --maxWorkers=1
npm run build
npx playwright install --with-deps chromium
node tools/smoke/run.mjs
```

Число работников задано для воспроизводимости измерений. На стандартном
раннере с четырьмя ядрами обычный запуск Vitest также использует три работника.
