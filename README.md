# Тирдаун

Воксельная игра-головоломка про ограбления с тотальной разрушаемостью.
Разведка уровня → пробитие кратчайшего пути → расстановка транспорта →
первая проводная цель включает сигнализацию → ровно шестьдесят секунд →
побег.

Играется в браузере. Друзьям ничего ставить не надо — только ссылка.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 559 тестов
npm run test:cov   # с порогами покрытия
npm run test:perf  # перф-регрессия, профиль в perf.json
npm run smoke      # прогон в настоящем браузере со скриншотами
npm run states     # ролики «цел → повреждён → разрушен» в shots/states
```

## Что уже работает

**Физическое ядро** (`packages/core`)

- Воксельный мир из форм и тел, DDA-трассировка луча, RLE-сериализация карт.
- Разрушение четырьмя кистями (сфера, бокс, капсула, конус) с моделью
  «сила инструмента против прочности материала»: кувалда не берёт сталь
  ни за двести ударов, паяльная лампа берёт.
- **Структурная целостность.** Флад-филл от якорей отделяет всё, что
  потеряло связь с землёй, в динамические обломки. Поверх — модель
  нагрузок: сжатие и изгиб с честным распределением веса по всем опорам
  куска. Подпилил колонну — плита села; отрезал балку — сел пролёт;
  деревянная консоль в четыре метра отламывается сама, стальная держит.
- Распространение огня: детерминированный клеточный автомат, обугливание,
  влага от огнетушителя, ветер.
- Твёрдые тела на Rapier: компаунд-коллайдеры из жадно склеенных боксов,
  пересборка по задетым чанкам, огрубление крупной геометрии, урон от
  удара по потере скорости. Тот же интерфейс реализует headless-дублёр —
  на нём гоняются тесты, и WASM для них не нужен.
- Обвал второго порядка: плита пробивает перекрытие, перекрытие теряет
  опору и падает дальше — цепочка сходится за конечное число шагов.
- Всё считается в бюджете кадра: грязь по чанкам, связность от изменений,
  напряжения в куске формы, взрыв порциями, обломки с потолком. Средний
  кадр симуляции при активном разрушении — около трёх миллисекунд.

**Игровая логика** (`packages/game`)

- Семь инструментов из дизайн-документа, по четыре ступени у каждого.
- Конечный автомат ограбления с таймером ровно на 60 секунд: доставка на
  59.9-й засчитывается, на 60.0 — вертолёт и провал без выплаты.
- Контроллер игрока, который сам заходит на завалы; техника, пробивающая
  стену на разгоне и расчищающая завал отвалом.
- Погоня: за двадцать секунд до конца из-за воды выходит вертолёт и
  приходит ровно к нулю таймера — гул винта и прожектор сообщают о
  времени раньше, чем цифра на экране. По воде отдельно идёт катер.
- Дым как объём, а не спрайты: он садит видимость в кадре и уводит прицел
  тем сильнее, чем гуще завеса между глазом и целью.
- Свет от неба по вокселям: внутри склада темно, а пробитая крыша кладёт
  на пол пятно света в том же кадре. Материалы читаются по блику —
  сталь бликует, грунт матовый, кабель сигнализации светится сам.
- Карта — файл, а не код: формат `tvox-level` с операциями геометрии,
  проверкой при загрузке и импортом моделей `.vox` из MagicaVoxel.
  Бросил файл в окно игры — играешь свою карту, пересборка не нужна.
- Кабель сигнализации проложен по стенам: снёс стену вместе с ним —
  сирена; обошёл аккуратно — вынес цель тихо.
- Эвакуация транспортом: цель кладётся в кузов, едет с машиной и
  засчитывается на въезде в зону; разбитая машина груз роняет, а не
  уносит с собой.
- Вода: катер идёт только по воде, пробитый корпус набирает воду и
  садится, утопленная машина глохнет насовсем.
- Экономика, прокачка в хабе, сохранение профиля и рекордов, песочница.

**Рендер и приложение** (`packages/render`, `apps/web`)

- Жадное меширование с затенением в углах, чанковый ремеш по бюджету.
- Частицы осколков, искр, дыма и огня; динамический свет от очагов.
- Звук без единого файла: удары синтезируются из шума с фильтром под
  материал, сирена — из двух расстроенных пил. Что и как громко звучит,
  решает игровой слой, и это покрыто тестами.
- Карта M «Порт»: набережная, склад, офис, кран, причал, контейнеры,
  гавань с водой. Пять целей, две из них на кабеле сигнализации.

## Устройство

```
packages/core    физика: воксели, разрушение, целостность, огонь, тела
packages/game    правила: инструменты, миссия, персонаж, техника, карты
packages/render  отрисовка: меширование, сцена, эффекты
apps/web         приложение: ввод, HUD, хаб, игровой цикл
tools/issues     волны issues и их заливка в GitHub
tools/smoke      прогон в браузере со скриншотами
tools/states     съёмка роликов состояний по материалам и инструментам
docs/states      эталонные ролики, с которыми сверяется ручная проверка
```

Ключевое разделение: **ядро и логика не знают про DOM и WebGL.** Поэтому
физика и правила покрыты обычными юнит-тестами (99% строк, 95% ветвей),
а рендер проверяется отдельно — скриншотами и прогоном в браузере.

Подробнее: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md),
план работ: [`docs/ROADMAP.md`](docs/ROADMAP.md).

## Управление

| | |
|---|---|
| WASD | движение |
| Shift / Ctrl | бег / присед |
| Пробел | прыжок, в воде — всплытие |
| ЛКМ | применить инструмент |
| ПКМ | детонатор |
| E | взять / положить цель, у машины — закинуть в кузов |
| G | выгрузить кузов (за рулём) |
| F | сесть в технику / выйти |
| V | вид от первого / третьего лица |
| N | день / сумерки / ночь |
| Q | качество: низкое / среднее / высокое |
| 1…7 | выбор инструмента |
| Колесо | листать инструменты |
| M | звук вкл/выкл |
| R | перезапуск |
| Esc | меню |
| Файл в окно | своя карта: `.json` в формате игры или `.vox` из MagicaVoxel |

## Волны issues

Работа нарезана на 13 волн и 57 задач с критериями приёмки —
`tools/issues/waves.yaml`.

```bash
npm run issues:plan                                    # посмотреть план
GH_TOKEN=… npm run issues:sync -- --repo owner/name    # залить в GitHub
GH_TOKEN=… npm run issues:sync -- --repo owner/name --close-done
# --close-done закрывает сделанные issues и вехи, где не осталось открытых
```

Скрипт идемпотентен: повторный запуск обновляет существующие issues,
сопоставляя их по заголовку, а не плодит дубликаты.

## Приёмка

1. Физика и игровая логика — только через тесты. Пороги 90% строк и 85%
   ветвей по `packages/core` и `packages/game` роняют сборку.
   Оптимизации ядра сверяются с честным полным пересчётом на сценариях
   карты: расхождение означает, что оптимизация врёт.
2. Рендер и цена кадра — через `npm run smoke`: прогон в Chromium,
   проверка на чёрный и на пересвеченный кадр, реальное разрушение,
   замер кадра симуляции во время обвала, скриншоты в `shots/`.
3. Любая случайность идёт через сид. Два прогона с одним сидом дают
   идентичное состояние мира, и на это есть тесты.
4. То, что видно только глазами, — через `docs/manual-check.md`:
   чек-лист ручной проверки и эталонные ролики в `docs/states`. Тест
   скажет, что снялось 812 вокселей; выглядит ли это как проломленная
   кладка, тест не решает. Свежие ролики снимает `npm run states`, и
   сравнивать надо их с эталонными, а не с воспоминаниями.
5. Производительность — через `npm run test:perf`: сценарий «заряд
   максимальной ступени в складе», зафиксированные бюджеты на кадр,
   ремеш, структуру, огонь и разрушение, профиль в `perf.json`. Прогон
   отдельный: под инструментовкой покрытия те же циклы идут вчетверо
   дольше, и мерить там нечего.
